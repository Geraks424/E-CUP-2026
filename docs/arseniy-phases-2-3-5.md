## Зафиксированный контракт

- `label=1` — качественный товар, итоговый вердикт `не бан`.
- `label=0` — некачественный товар, итоговый вердикт `бан`.
- Выход: CSV только с колонками `id`, `result`.
- `result`: `<комментарий>...<вердикт>бан|не бан`, без закрывающих тегов.
- Длина комментария: от 50 до 300 символов.
- Требуется результат для каждого входного `id`, без дубликатов и дополнительных `id`.
- Метрика: среднее F1 по категориям `БАД` и `Легковоспламеняющиеся`.

`run.py` принимает обе формы официальных и baseline-аргументов:

```text
--test_data_path | --test-data-path | -i
--output_path    | --output-path    | -o
```

## Фаза 2 — rule-engine и Result-стадия

Реализация: `baseline/quality-baseline-submit/src/rules.py`.

Правила не заменяют модель. Модуль возвращает:

- предварительный `label`;
- `rule_score` от `-1` до `1`;
- коды сработавших правил;
- найденные в карточке фрагменты;
- текстовое основание решения.

Для БАД реализованы только указанные организаторами признаки:

- прямая маркировка `БАД`, `биологически активная добавка`, `dietary supplement`;
- прямое отрицание принадлежности к БАД;
- признаки спортивного питания: аминокислоты, BCAA, L-карнитин, протеин;
- отсутствие прямой маркировки.

Для легковоспламеняющихся реализованы:

- самостоятельные источники воспламенения;
- горючие вещества и газовые баллоны;
- отсутствие горючего содержимого или предмета в комплекте;
- устройство для работы с огнём без содержимого;
- горючий материал только как компонент изделия.

Постпроцессинг в `src/utils_postprocess.py`:

- удаляет reasoning и внедрённые моделью теги;
- не теряет строки при пустом или коротком ответе LLM;
- использует детерминированное объяснение, если LLM не вернула валидный текст;
- принудительно соблюдает длину и связку `label ↔ вердикт`.

## Фаза 3 — классификатор БАД

Реализация: `src/bad_classifier.py`. Артефакт:

```text
baseline/quality-baseline-submit/arseniy_bad_text_model.joblib
```

Состав модели:

- word TF-IDF, n-граммы 1–2;
- char TF-IDF, n-граммы 3–5;
- пять явных rule-признаков;
- логистическая регрессия с `class_weight=balanced`;
- порог, подобранный только по out-of-fold вероятностям.

Валидация выполнена через пятифолдовый `StratifiedGroupKFold`. Группа — точное нормализованное название товара, поэтому одинаковые названия не оказываются одновременно в train и validation.

### Измеренный результат на `data.csv`

| Показатель | Значение |
|---|---:|
| Строк БАД | 7 469 |
| `label=0` / `label=1` | 1 905 / 5 564 |
| OOF threshold | 0.465 |
| OOF F1 БАД | **0.952079** |
| Precision | 0.959817 |
| Recall | 0.944464 |
| FP / FN | 220 / 309 |
| Rules-only F1 | 0.801259 |
| Размер артефакта | 2 689 248 байт |

Это оценка только головы БАД. Она не является оценкой общего Macro F1 и напрямую не сравнивается с отчётом Phase 0 на 50 строках, где использовались другая выборка и мультимодальный baseline.

Полный отчёт: `reports/arseniy/phase3-bad.json`. Все 529 OOF-ошибок с вероятностями и rule-сигналами: `reports/arseniy/phase3-bad-errors.csv`.

В данных есть карточки, где текстовая маркировка и метка расходятся. Например, встречаются `label=0` при прямом тексте `БАД`. Такие строки не переименованы и не удалены: изображение или разметка могут содержать недоступный текстовой модели контекст.

Обучение воспроизводится командой:

```powershell
python scripts\train_bad_classifier.py --data_csv D:\data.csv
```

## Фаза 5 — объяснения

Промпт находится в `src/explanations.py`, генерация — в `src/utils_generate_cuda.py`.

- Вердикт передаётся LLM как уже зафиксированный и не должен изменяться.
- В промпт включены правила только выбранной категории.
- Передаются найденные rule-engine фрагменты, если они согласуются с итоговым классом.
- Запрещено добавлять факты, которых нет в карточке.
- LLM возвращает только комментарий; теги и вердикт добавляет детерминированный постпроцессинг.

Для CPU-smoke или гарантированного fallback доступен режим:

```powershell
python run.py ... --comments_mode rules
```

Набор из 10 автоматически выбранных эталонных объяснений находится в `reports/arseniy/explanation-golden-set.csv`. Для двух правил — английского `dietary supplement` и горючего материала только как компонента — в train не найдено примеров, у которых одновременно совпали текстовый rule-сигнал и целевая метка; примеры для них не выдумывались.

Пересборка набора:

```powershell
python scripts\build_explanation_golden_set.py --data_csv D:\data.csv
```

## Интеграция

`run.py` сначала получает мультимодальные эмбеддинги и baseline-прогнозы для всех строк. Затем:

- строки `БАД` заменяются прогнозами артефакта Арсения;
- строки `Легковоспламеняющиеся` остаются за мультимодальной головой baseline/Phase 4;
- объяснение получает категорию, окончательный класс и трассируемый rule-сигнал;
- Result-постпроцессинг гарантирует валидный CSV.

CPU-only проверка компонентов Арсения на всём train без загрузки VLM:

```powershell
python scripts\smoke_arseniy_components.py --input_csv D:\data.csv
python scripts\validate_quality_submission.py `
  --input_csv D:\data.csv `
  --submission_csv local_data\arseniy_components_smoke.csv
```

Фактический результат локального smoke: **12 971 / 12 971 строк прошли Result-валидатор**.

## Границы выполненной работы

- БАД-модель Арсения использует `name` и `description`; изображения остаются в существующем мультимодальном baseline и последующей интеграции.
- Архив `images.zip` не загружался в эту рабочую папку: его размер около 8.56 GiB без учёта распаковки.
- Полный Docker/H100-прогон с Qwen-моделями требует локально доступных `SHARED_MODELS_PATH`, изображений и CUDA. Он относится к фазе 6 и здесь не заявляется как выполненный.
- Улучшение общего Macro F1 можно утверждать только после совместной валидации новой головы БАД и головы легковоспламеняющихся на одном закрытом или честно отложенном мультимодальном наборе.
